# 复现范围

目标是复现 agent demo 的技术执行流程，并完善 harness 工程。公开实现使用
合成输入和可替换的工具/知识库接口；不实现私有数据接入，不包含真实知识库语料。

## 当前实现及其边界

| 已有能力 | 目前能够验证什么 | 尚不能证明什么 |
|---|---|---|
| 工具参数契约 | 当前 mock 工具的参数校验 | 目标工作流的工具定义已经复现 |
| 有界重试与超时处理 | 注入失败后的状态结果 | 真实外部系统的可靠性 |
| SQLite 幂等记录 | mock 副作用与记录原子提交、重启去重 | 分布式外部副作用的 exactly-once |
| JSONL 追踪与回放 | 验证状态序列、重建执行结果 | 自动断点恢复或完整工作流重跑 |
| 合成登录/MFA 场景 | 执行器的测试夹具 | 目标项目的业务流程或检测质量 |

## 后续实现的归属

每个新增模块应明确属于下列一类：

- **流程复现**：来自已核实技术方案的节点、输入输出、状态流转与停止条件。
- **工程补强**：为了让 demo 可运行、可调试、可验证而新增的 harness 能力。
- **合成替代**：模拟私有数据入口、工具返回或知识库内容，注明与真实依赖的差异。

现有登录规则不能用来反推目标技术方案。完整工作流需要先确认节点之间的关系、
状态传递和工具契约，再替换当前测试场景。架构、技术栈和业务效果不能在未核实
时写成已复现能力。

## 可公开的验收证据

采用合成案例，保存输入版本、配置、预期行为和执行轨迹；分别报告正常路径与失败
路径是否满足契约。真实数据接入和知识库语料由替代接口承担，不属于 demo 的
验收依赖。复现的流程与自行增加的工程能力应在文档中分别标明。
